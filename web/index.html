What it catches

  
Four kinds of bugs it detects, and two workflow features that make checking practical.

  

    
Detects
Stale drawer
The item is stored but the cart drawer still says empty or shows the old lines.

    
Detects
Wrong variant
The shopper picked Blue and the theme stored Red, or the drawer shows a different variant than the cart.

    
Detects
Quantity or stock clamp
The drawer shows the quantity requested while the store kept fewer.

    
Detects
Markets currency or total mismatch
The right number with the wrong currency sign, a wrong amount, or a total that disagrees with the stored cart.

    
Workflow support
Password-protected dev stores
Checks development stores behind a storefront password. Preview-theme setup has its own guide with limits.

    
Workflow support
HTTP 429 pacing
Spaces requests per store, honours Retry-After and retries once. It reduces throttling; it can't promise it never happens, and a throttled case is reported as BLOCKED, never PASS.

FAQ

  
Why does the Dawn cart drawer show an empty or stale cart while /cart.js already has the item?
Dawn's product form posts to /cart/add.js and asks Shopify to return the re-rendered cart drawer and cart icon sections in the same response; the drawer then swaps in that HTML. If a customization, an app script or a missing section breaks that swap, Shopify has stored the item (it is in /cart.js) but the shopper still sees the old drawer and badge. MarketCart CI reads /cart.js independently of the page and compares it with what the drawer shows; any difference is a REGRESSION with the exact mismatch.

  
How do I catch a Shopify Markets currency mismatch in the cart?
Check three things in the same browser session: the market Shopify actually served (window.Shopify.country and window.Shopify.currency.active), the stored cart currency in /cart.js, and the currency shown next to every visible price and the total. They must agree, with no conversion applied. MarketCart CI does exactly that; if the session never gets the requested market, the result is UNSUPPORTED rather than a PASS you cannot trust.

  
How can I run cart regression tests in CI before publishing a Shopify theme?
Run the open-source MarketCart CI CLI or GitHub Action on every theme change. Describe cases as JSON (product URL, variant, quantity, market), optionally as a pair: the published theme versus an unpublished theme preview. The job exits 0 on PASS, 1 on REGRESSION and 2 when a case is inconclusive, so a failing cart blocks the deploy. Local runs are free; hosted runs use prepaid case credits.
