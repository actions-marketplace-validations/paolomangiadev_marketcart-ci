Shopify Markets currency mismatch in the cart: test stored vs visible currency and totals

With Shopify Markets a shopper can be served a different currency than your default. Three things must agree in the same browser session: the market the session actually got, the currency of the stored cart, and the currency shown next to every visible price and the total. When one of them drifts (a hard-coded symbol in a snippet, an app that formats prices itself, a cached drawer from another market) the shopper sees one number and pays another.

Where each value comes from

  • Stored cart: GET /{locale}/cart.js. Shopify's reference says all monetary properties are returned in the customer's presentment currency, and the currency field tells you which. Ajax amounts are integers in hundredths (2400 = 24.00).
  • Session market: in Liquid, localization.country and localization.country.currency.iso_code; in the browser, storefronts expose window.Shopify.country and window.Shopify.currency.active (a de-facto global, not a documented contract, so read it defensively).
  • Visible prices: the rendered drawer or cart page text, e.g. €24.00, 24,00 €, $24.00.

The rules a test should apply

  1. Verify the market first. If you asked for IE/EUR and the session reports US/USD, the test is inconclusive, not a pass and not a regression: you did not test the market you meant to.
  2. The stored cart currency must equal the session currency.
  3. Every visible price must carry an indicator of that currency and the same amount as the stored line. A price with no currency indicator is unverifiable, not correct.
  4. Never convert. If amounts only match after applying an exchange rate, they do not match.

Minimal in-page check

// paste in DevTools on your own store after adding an item
const cart = await (await fetch(Shopify.routes.root + 'cart.js')).json();
const session = Shopify.currency?.active;
console.log({ storedCurrency: cart.currency, sessionCurrency: session,
  same: cart.currency === session,
  total: (cart.total_price / 100).toFixed(2) });

Then compare with the rendered total. For CI across markets, give each case its market ({"country":"DE","currency":"EUR"}) and the market URL a shopper would use; MarketCart reports UNSUPPORTED when the session never gets that market.

Limits

Zero-decimal currencies (JPY, KRW) rely on Shopify's “×100 for every currency” Ajax convention, verified on synthetic data only. Indian lakh digit grouping is not parsed (returns UNSUPPORTED). Create a CI workflow with the workflow generator.
