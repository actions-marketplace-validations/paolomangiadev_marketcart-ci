GitHub Actions: E2E cart test of a Shopify preview theme before publishing

Short answer: on each pull request, push the branch as an unpublished theme with Shopify CLI (theme push --unpublished --json returns the theme id and a preview_url of the form https://your-store.myshopify.com/?preview_theme_id=ID), run the same cart case against the live theme and against the preview, fail the job if the preview regresses, then delete the preview theme. Keep every credential in Actions secrets.

What is verified and what is not

PartStatus
Password-protected development store (Dawn 16.1.1), cart page, storefront password sent from a secretVerified live: paced suite 7/7 and hosted runs 2/2 (November 2026)
Live vs candidate comparison, idempotent job id, pacingVerified on the synthetic store and in the hosted service tests
Unpublished preview themes on a real storeNot verified. MarketCart CI keeps the preview_theme_id query parameter in case URLs and runs each side of a pair in its own fresh browser session, but we have not confirmed on a live store that Shopify keeps serving the preview theme through add-to-cart and /cart.js in that session

Until that is verified, treat a preview-side result as a strong hint, and confirm once by hand: open the preview_url in a private window, add the product, and compare the drawer with /cart.js. If the preview banner disappears or the drawer shows the live theme's markup, the preview context did not persist and the candidate result is not meaningful for that store.

Prerequisites

  • Secrets: SHOPIFY_STORE (your-store.myshopify.com), SHOPIFY_CLI_THEME_TOKEN (a Theme Access app password, which Shopify CLI reads from that variable), MARKETCART_LICENSE, and MARKETCART_STOREFRONT_PASSWORD only if the store is password-protected. GitHub does not pass secrets to workflows triggered from forks, so the job skips fork pull requests.
  • Ownership: the hosted runner only checks stores that carry your verification meta tag in the live theme's <head> (one-time setup).
  • A product URL with ?variant= from your store.

The workflow

name: preview-theme-cart-check
on:
  pull_request:
permissions:
  contents: read
concurrency:
  group: preview-cart-${{ github.event.pull_request.number }}
  cancel-in-progress: false  # never cancel a hosted job halfway; a re-run is a new job id
jobs:
  preview-cart:
    # Fork pull requests get no secrets: skip instead of failing.
    if: github.event.pull_request.head.repo.full_name == github.repository
    runs-on: ubuntu-latest
    env:
      SHOPIFY_FLAG_STORE: ${{ secrets.SHOPIFY_STORE }}                 # your-store.myshopify.com
      SHOPIFY_CLI_THEME_TOKEN: ${{ secrets.SHOPIFY_CLI_THEME_TOKEN }}  # Theme Access app password
      PRODUCT_PATH: /products/your-product?variant=1234567890          # a product of YOUR store
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '22'
      - name: Push this branch as a new unpublished theme
        run: npx --yes @shopify/cli@5.0.1 theme push --unpublished --json --path . > theme.json
      - name: Write cases (live theme vs this preview)
        run: |
          mkdir -p marketcart
          node -e '
            const t = require("./theme.json").theme;
            const host = process.env.SHOPIFY_FLAG_STORE;
            const url = "https://" + host + process.env.PRODUCT_PATH;
            const variantId = Number(new URL(url).searchParams.get("variant"));
            const sep = url.includes("?") ? "&" : "?";
            const cases = { authorizedDomains: [host], cases: [{
              id: "pdp", market: { country: "US", currency: "USD" },
              lines: [{ url, variantId, quantity: 1 }],
              candidate: { lines: [{ url: url + sep + "preview_theme_id=" + t.id, variantId, quantity: 1 }] } }] };
            require("fs").writeFileSync("marketcart/cases.json", JSON.stringify(cases, null, 2));
            require("fs").writeFileSync("theme-id.txt", String(t.id));'
      - id: marketcart
        uses: paolomangiadev/marketcart-ci@v0.2.0
        with:
          mode: remote
          cases: marketcart/cases.json
          license: ${{ secrets.MARKETCART_LICENSE }}
          storefront-password: ${{ secrets.MARKETCART_STOREFRONT_PASSWORD }}
          source: preview-ci
      - name: Delete the preview theme
        if: always()
        run: test -f theme-id.txt && npx --yes @shopify/cli@5.0.1 theme delete --theme "$(cat theme-id.txt)" --force || true

The case writer was run on the sample output that Shopify documents for theme push --json; for theme id 108267175958 it produces a candidate URL ending in ?variant=1234567890&preview_theme_id=108267175958.

Credits, retries and pacing

  • Idempotent jobs: the job id is derived from GITHUB_RUN_ID and GITHUB_RUN_ATTEMPT. Resending the same job (network retry) is not billed twice; re-running the workflow is a new attempt and a new job.
  • Billing: a pair uses 2 credits; only PASS and REGRESSION use credits, BLOCKED/UNSUPPORTED/ERROR are released.
  • Pacing: cart cycles on one store are spaced 15 s apart and Retry-After is honoured; a store that keeps answering 429 returns BLOCKED, never PASS. concurrency keeps pushes to the same pull request from piling up.
  • Isolation: each side runs in a new browser context: no cookies or cart carried over between live and preview.

Expected output

| Case | Status | ms | Reason |
|---|---|---:|---|
| pdp | PASS | … | live PASS, candidate PASS |

exit code 0   (1 = the preview regressed, 2 = inconclusive, 3 = license/API problem)

The table shape is the CLI's real format; the row is illustrative, since this exact workflow has not been run against a real preview theme.

Troubleshooting

  • theme push asks for a theme: non-interactive runs need one of --unpublished, --theme, --development or --live.
  • Unpublished themes pile up in the theme library, one per run: keep the delete step (theme delete --theme ID --force).
  • Exit 3: license missing (fork pull request or secret not set) or the store's ownership tag not found.
  • UNSUPPORTED on the candidate: the preview theme has no supported adapter, or the market was not served.

Limits

Dawn family and Horizon 4.4 only. Live preview themes not verified (above). Never opens checkout, never edits store settings.
