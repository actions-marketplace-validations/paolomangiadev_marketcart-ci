Testing Shopify cart drawer web components with Playwright (Dawn <cart-drawer>, Horizon <theme-drawer>)

Short answer: scope every selector to the drawer element, wait for the drawer's rendered state (open, one visible row per stored line) instead of a fixed sleep, compare it with /cart.js fetched in the same session, and never navigate to /cart to "check the cart": the cart page is rendered fresh by the server and hides a stale drawer.

What the drawer actually is

Dawn 16.1.1 (snippets/cart-drawer.liquid, assets/cart-drawer.js): a custom element <cart-drawer class="drawer"> wrapping <div id="CartDrawer" class="cart-drawer"> and <cart-drawer-items>; it gets is-empty while the cart is empty. Opening adds the class active. After Add to cart, product-form.js posts to /cart/add with a sections parameter listing the drawer's sections (cart-drawer, cart-icon-bubble) and sections_url; CartDrawer.renderContents() swaps the returned HTML into #CartDrawer and the header bubble, then calls open(). The header icon #cart-icon-bubble opens the drawer on click.

Horizon 4.4.0 (snippets/cart-drawer.liquid at the v4.4.0 commit): the drawer is rendered only when the theme setting cart_type is drawer and the template is not cart. Markup: <theme-drawer id="cart-drawer"> > native <dialog class="theme-drawer__dialog"> > <cart-drawer-component>, which carries auto-open only when auto_open_cart_drawer is enabled. assets/theme-drawer.js opens the panel with showModal(), so "open" means dialog.open === true. Rows are tr.cart-items__table-row.

A complete check

// Cart drawer vs /cart.js for Dawn 15/16 (<cart-drawer>) and Horizon 4.4 (<theme-drawer id="cart-drawer"><dialog>).
// npm i playwright-core@1.64.1 && npx playwright-core install chromium-headless-shell
// node drawer-check.mjs "https://<store>/products/<handle>?variant=<id>"
import { chromium } from 'playwright-core';

const THEMES = {
  dawn: { add: 'product-form button[name="add"]', drawer: 'cart-drawer', trigger: '#cart-icon-bubble', rows: 'cart-drawer .cart-item' },
  horizon: {
    add: 'add-to-cart-component button[name="add"], product-form-component button[name="add"]',
    drawer: 'theme-drawer#cart-drawer dialog',
    trigger: 'button[aria-controls="cart-drawer"], [data-testid="cart-drawer-trigger"]',
    rows: 'theme-drawer#cart-drawer dialog tr.cart-items__table-row:not(.cart-items__nested-line)',
  },
};
const isOpen = (sel) => { const d = document.querySelector(sel); return !!d && (d.classList.contains('active') || d.hasAttribute('open') || d.open === true); };

const browser = await chromium.launch();
const page = await browser.newPage();
await page.goto(process.argv[2]);
const schema = await page.evaluate(() => window.Shopify?.theme?.schema_name ?? '');
const t = schema.toLowerCase() === 'horizon' ? THEMES.horizon : THEMES.dawn;
if ((await page.locator(t.drawer).count()) === 0) throw new Error('no cart drawer on this page (cart type "page"): test the cart page instead, deliberately');

const added = page.waitForResponse((r) => /\/cart\/add(\.js)?$/.test(new URL(r.url()).pathname));
await page.click(t.add);
const status = (await added).status(); // 200 = Shopify stored it; 422 = rejected (sold out, quantity), 429 = throttled
const stored = await page.evaluate(async () => (await fetch(window.Shopify.routes.root + 'cart.js')).json());

// Wait for the RENDERED state instead of a fixed sleep: drawer open and one visible row per stored line.
// If the theme never re-renders the drawer, this times out and the check reports what is actually on screen.
const want = stored.items.length;
const rendered = await page
  .waitForFunction(({ drawer, rows, want }) => {
    const d = document.querySelector(drawer);
    const open = !!d && (d.classList.contains('active') || d.hasAttribute('open') || d.open === true);
    return open && [...document.querySelectorAll(rows)].filter((r) => r.getClientRects().length).length === want;
  }, { drawer: t.drawer, rows: t.rows, want }, { timeout: 5000 })
  .then(() => true, () => false);
if (!(await page.evaluate(isOpen, t.drawer))) await page.click(t.trigger); // auto-open off: open it like a shopper

const visibleRows = await page.locator(t.rows).filter({ visible: true }).count();
const ok = status === 200 && visibleRows === want;
console.log({ theme: schema, addStatus: status, storedLines: want, storedQty: stored.items.map((i) => i.quantity), drawerRendered: rendered, visibleRows, result: ok ? 'PASS' : 'REGRESSION' });
await browser.close();
process.exitCode = ok ? 0 : 1;

Why /cart hides the bug

The stale-drawer failure is a client-side swap that did not happen: the add succeeded (HTTP 200, /cart.js has the line) but the section HTML never replaced the drawer, for example because a customization renamed a section the drawer requests or an app script replaced the drawer markup. Loading /cart asks the server for a fresh render of the stored cart, so it shows the right line and the test passes while shoppers still see "Your cart is empty".

Troubleshooting

  • Timeout waiting for rows on a healthy store: the drawer may not auto-open (Horizon: auto_open_cart_drawer off). Open it from the header control, as above, before reading it.
  • Rows found but zero visible: templates (<template id="empty-cart-template"> in Horizon) and closed drawers contain markup too. Count only rows with client rects.
  • Shadow DOM: the drawer elements above live in the light DOM (no attachShadow in Dawn's cart-drawer.js or Horizon's theme-drawer.js/cart-drawer.js); Playwright CSS selectors would also pierce open shadow roots.
  • 422 on add: Shopify rejected the add (sold out, quantity over stock, unknown variant); see 422 vs 429. 429: you are adding too fast; space runs out.

Limits

Selectors checked against Dawn v15.4.1/v16.1.1 and Horizon v4.4.0 source; other versions and themes may differ.
