Shopify cart.js returning 422 or 429: test it without retrying the wrong thing

Two very different failures come back from the Shopify Ajax Cart API. 422 means Shopify understood the request and refused it; 429 means you are being throttled. A cart test that treats them the same either retries a request that can never succeed, or turns throttling into a red build.

422: the cart rejected the operation

From the official Ajax Cart API reference, POST /{locale}/cart/add.js answers 422 with a JSON body such as:

{ "status": 422, "message": "Cart Error", "description": "Cannot find variant" }

Documented cases: the variant does not exist or is not available in the online store channel (Cannot find variant); the product is sold out (The product '…' is already sold out.); the requested quantity exceeds stock (You can't add more … to the cart.). Note the last one: Shopify documents that it adds the maximum available quantity and still returns the error, so the stored cart can change even though the request "failed".

Testing rule: a 422 is a semantic answer. Do not retry it blindly; record it, and treat the case as inconclusive for parity (the cart you asked for does not exist). The one documented exception is a variant you created or published seconds ago: Shopify says to retry after a short, increasing delay and to stop after a few attempts.

429: you are being throttled

The same reference warns that repeated failed attempts to add items to the same cart are throttled and return 429. In our own paced tests on a password-protected development store, rapid cart cycles also hit 429 on the product page and on /cart.js after about four cycles in under a minute (our observation, not a published limit).

Testing rule: wait, then try once more in a fresh session. Honour Retry-After when it is present (seconds or an HTTP date); otherwise back off exponentially with jitter and a ceiling. Never count a 429 as a pass, and never rotate IPs or proxies to get around it.

Minimal check you can run

// node check-add.mjs https://your-store.myshopify.com 123   (Node 18+; run against a store you own)
const [base, variant] = process.argv.slice(2);
const r = await fetch(new URL('/cart/add.js', base), {
  method: 'POST',
  headers: { 'content-type': 'application/json', accept: 'application/json' },
  body: JSON.stringify({ items: [{ id: Number(variant), quantity: 1 }] }),
});
const body = await r.json().catch(() => ({}));
if (r.status === 422) console.log('REJECTED (do not retry):', body.description);
else if (r.status === 429) console.log('THROTTLED, retry after', r.headers.get('retry-after') ?? 'backoff', 's');
else if (r.ok) console.log('ADDED', body.items?.map((i) => [i.variant_id, i.quantity]));
else console.log('HTTP', r.status);

A plain fetch has its own cookie jar, so this exercises the API, not a shopper's browser session. For the visible side (drawer, badge, totals) use a real browser.
