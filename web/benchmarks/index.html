This shows which bug classes are detected, not that every live store behaves alike.

Theme coverage and where each result comes from

  • Theme/surface matrix (synthetic): version-pinned skins Dawn 15.4.1 and 16.1.1 and Horizon 4.4.0, drawer and cart page: 63/63 as expected, 0 false PASS (scripts/theme-matrix.ts, evidence/theme-matrix/latest.json in the repository).
  • Live Dawn 16.1.1 cart page on a password-protected development store: paced suite 7/7, including 5 consecutive healthy PASS and 1 recovered HTTP 429; hosted parity 2/2 PASS (evidence/live/).
  • Not live-verified: the Dawn drawer, Horizon (drawer and page) and preview themes. They are verified on version-pinned synthetic markup only.

Limits, stated plainly

  • Themes: Dawn family and Horizon 4.4.0. Other themes return UNSUPPORTED, never PASS.
  • A theme with a cart drawer is tested on the drawer; a closed or stale drawer is never replaced by the (fresh) cart page.
  • Hosted runs pace each store (15 s between cart cycles, Retry-After honoured, one retry). A job that cannot start a case within about 4.5 minutes returns that case as BLOCKED (queued) and releases its credit.
  • Never opens checkout, never submits payment, never logs in, no anti-bot evasion. Bot challenges and HTTP 429 return BLOCKED.
  • The market is verified inside the session; no currency conversion is ever applied. Zero-decimal currencies rely on Shopify's ×100 Ajax convention, verified on synthetic data only.
  • Shopify still rate-limits rapid cart traffic; pacing reduces it but cannot promise it never happens. Concurrency 1 in hosted mode.
